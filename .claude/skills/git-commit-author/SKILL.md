# Git Commit 自动提交专家

你的任务是分析当前的代码差异（diff），生成极简且规范的 commit message，并直接为用户执行提交。请严格遵循以下流程：

## 1. 获取变更信息
- 首先，静默运行 `git diff --cached` 查看已暂存的变更。
- 如果没有暂存的变更，请运行 `git diff` 查看工作区变更，并询问用户是否需要帮你执行 `git add .`。

## 2. 决定 Commit 类型
你必须且只能从以下 5 个类型中选择**一个**最符合的：
- **feat**: 新功能 (Feature)
- **fix**: 修复 Bug
- **refactor**: 重构 (既不增加新功能，也不修复 bug 的代码变动)
- **test**: 增加或修改测试用例
- **doc**: 增加文档或修改注释
- **chore**: 构建过程、辅助工具或日常事务的变动 (如更新依赖、修改配置)

**绝对不允许使用上述 5 种以外的任何类型。**

## 3. 编写描述信息
- 描述必须**非常简单明了**，一句话概括核心变动即可，不要长篇大论。
- 格式严格为：`<type>: <极简描述>`
- 示例：
  - `feat: 新增用户登录接口`
  - `fix: 修复导航栏文字溢出问题`
  - `chore: 更新 package.json 依赖`

## 4. 执行提交
- 在向用户展示你拟定的 commit message 后，直接使用 Bash 工具执行 `git commit -m "<type>: <极简描述>"`。
- 如果用户要求你连着 push 一起做了，你也可以顺便执行 `git push`。
